# JANUS experiment contract, revision 1

IDs M01–M12, Q01–Q20 and O01–O08 use the approved plan's names and priorities. A run ID is `<case>-<engine>-<variant>`; label archive and newly executed runs separately. Record case, variant, fixture/event schedule, model and command hashes, software, solver and log sample periods, seed, termination reason and evidence paths in each run manifest. Archive, synthetic projection, image decoding, offline replay, native runtime and physical trial are separate evidence scopes. Cases with unmeasured acceptance conditions are partially evidenced or blocked, even when a subsidiary check passes.

## Geometry, units and clocks

SI units. World frame is right-handed, origin at initial axle midpoint unless scenario says otherwise. Robot body/drive frame is axle midpoint, x forward, y left, z up, and yaw positive anticlockwise about +z. Positive drive speed/ticks correspond to forward motion on both wheels. Left/right labels follow the robot looking forward. Report camera optical frame separately (x right, y down, z forward). Declare fixed transforms and calibration provenance, including nominal assumptions. Use run-relative `time_s` monotonic from 0, `capture_time_s` and `arrival_time_s` in the same clock domain, and unit-tagged columns. Record clock reset explicitly, and use a new run ID after restart. Compare at a stated sample grid using interpolation for continuous measurements, unwrapped yaw for interpolation, and zero-order hold for commands/events. Distinct producer/consumer timestamps do not substitute for an independently synchronized clock.

## Commands and observations

- Velocity CSV: `time_s,v_mps,yaw_rate_radps`. Distinguish requested versus executed/limited command and whether replay uses one or the other.
- Applied axle torque CSV: `time_s,tau_left_Nm,tau_right_Nm`, zeros explicitly present where applied, zero-order hold. Include initial pose, velocities, caster relative angle and solver/grid in the companion manifest. Never infer equal effort from equal Twist commands.
- QR observation: capture/arrival time, width_px, height_px, ID, four corners in physical marker order (top-left, top-right, bottom-right, bottom-left when upright), center u/v in image pixels, visible/valid and quality or reject reason; include source (projection, decoded image, or replay). A frame may contain zero or several candidates. The stations fixtures use ID JANUS-DOCK-01 unless the case specifies a different test identity; publishers record their actual ID and map it explicitly in comparisons. Calibration/fixture metadata supplies target_u_px and transforms. Normalized horizontal error is (center_u_px − target_u_px)/width_px. Positive error (right of target) commands negative yaw, negative error commands positive yaw.
- Dock driving starts after +/−2% centering for 0.4 s continuous fresh valid observations, re-centers with zero forward command outside +/−4%, and disallows forward drive on missing, wrong, stale or disordered observation. Declare freshness limit (default 0.20 s) and age source. Gate aligned/contact/charge_confirmed separately, with BMS freshness and evidence source. Any thresholds changed for a sensitivity study are explicit.
- Minimum results include body x/y/yaw, yaw rate and forward velocity, applied left/right wheel torque and wheel speed where measured, caster relative angle and swivel rate, phases/reason flags and event times. Contact and charge signals specify physical/simulated/absent. V2.3 terminal gate uses ≤0.02 m pose error, ≤0.05 rad yaw error, ≤0.02 m/s speed, ≤0.05 rad/s yaw rate, continuously 0.25 s. M05/M06 also log four edge and four 90° turn gates using the plan's 5 cm/5° corner limits.

`commands/` holds verified per-case time series generated by each workstream. Exact schema above, with per-run provenance and command sign checks.
