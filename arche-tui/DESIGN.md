# Dashboard implementation

The supplied s-tui reference uses a persistent narrow control column, four vertically stacked charts, a charcoal background and purple/pink/lime/orange graph colours. The old console hid operations behind tabs and shortcuts and required vector JSON entry. The replacement keeps model choice, run/stop, parameter groups and result actions visible. It separates recorded data from the current solver stream and exposes coordinate fields individually.

The dashboard uses curses already included with Python; it adds no dependency. It reuses the existing adapter and result viewers. Live observation wraps result_record only and writes an atomic progress snapshot every 0.25 wall seconds, keeping at most 600 samples. The underlying integration and control equations are unchanged.

Validation: complete V1 and V2 default runs were launched from a real terminal. Saved numeric results were compared with the MATLAB V1 reference and archived V2 baseline. Automated tests cover both kernels with and without live observation, mouse hit targets, numeric replacement, independent model drafts, equal-scale XY rasterisation and layouts at 80x24 and 125x40. Pillow previews render the actual terminal drawing calls using saved model data; they are renderer previews, not native OS screenshots. Browser rendering of the inherited HTML viewer has not been manually checked in this redesign.

The opening page provides default V1/V2 example buttons and a short editable input list. The full experiment list remains available through All experiment inputs. Eight short guide pages explain the actions and meanings inside the terminal; page controls work with mouse or keyboard. Guide pagination and field paging keep all content accessible at 80x24. The English interface text uses direct instructions and explains when a button resets edited inputs.

Keyboard navigation uses one ordered set of controls per page, including all fields in long lists. Tab and Shift-Tab traverse both the sidebar and page; arrows move within the focused area. Enter activates the highlighted control. Home/End jump within that area. S, R, G and M label the presentation path in the top row; F2, F3 and F4 also open setup, graphs and results. A bounded history restores the previous page and its focused control with Esc/Backspace. Completed background runs preserve the page being read.

The primary keyboard flow uses model number + Enter. Input fields carry direct A-F keys, and long parameter lists show six fields per page. Dropdown numbers select options immediately. The setup page has one run action; a selected default can be reset and run with W. After completion, Enter opens caster motion, then results, then setup. The numbered left menu and contextual footer expose direct actions without requiring focus navigation.
